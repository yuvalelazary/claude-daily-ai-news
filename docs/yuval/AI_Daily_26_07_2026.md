## חדשות היום

### 1. xAI מקודדת את Grok-Build כקוד פתוח בעקבות פרצת נתונים ענקית

לאחר שנתגלה כי כלי הקידוד Grok-Build של xAI העלה בשקט מאגרי Git שלמים לשרתי Google Cloud — כולל מפתחות SSH, מסדי נתונים ומסמכים אישיים — החליטה החברה לפרסם את כל הקוד כקוד פתוח תחת רישיון Apache 2.0. מחסן הקוד הכולל כ-844,000 שורות Rust פורסם ב-GitHub, ולפי xAI כל הנתונים שנאספו נמחקו לצמיתות. עם זאת, החברה לא מסרה כמה משתמשים נפגעו ולא סיפקה כל אישור חיצוני למחיקה.

### 2. OpenAI משיקה GPT-5.6 Sol — לאחר תקופת גישה ממשלתית בלעדית

OpenAI השיקה את GPT-5.6 Sol, Terra ו-Luna לציבור הרחב לאחר 12 ימים שבהם הגישה הוגבלה לכ-20 גופים ממשלתיים שעברו אימות. Sol, המודל הדגל לביצוע משימות אגנטיות מורכבות, השיג 96.7% במבדק ההגנה הסייברנטית הפנימי של OpenAI ומגיע בשליש מעלות ההסקה של מודלים מתחרים. הזמינות ניתנת עכשיו דרך ChatGPT, ה-API ו-Codex.

### 3. Anthropic מרחיבה את הגישה החינמית ל-Fable 5 על רקע מלחמת מחירים עם OpenAI

בתגובה להשקת GPT-5.6 Sol, הכריזה Anthropic כי מאריכה את הגישה החינמית למנויים למודל Fable 5 — המתחרה הישיר של Sol. המהלך מגיע כחלק מתחרות מחירים גוברת בין שתי החברות הגדולות בתחום הבינה המלאכותית. מנויים מקבלים גישה למודל המלא ללא עלות נוספת כל עוד הפרומוציה בתוקף.

### 4. קונסורציום גרמני משחרר את Soofi S — מודל פתוח עם 30 מיליארד פרמטרים

קבוצת מחקר גרמנית שיתופית שחררה את Soofi S, מודל שפה פתוח בגודל 30B שאומן כולו על תשתית ה-AI של Deutsche Telekom. המודל מצטיין בבנצ'מרקים בגרמנית, אנגלית ומשימות תכנות, ומוביל בין כל המודלים הפתוחים לחלוטין בשתי השפות. השחרור ממשיך את המגמה האירופית לפתח תשתיות AI ריבוניות עצמאיות.

### 5. ChatGPT חוזר ל-WhatsApp באירופה בעקבות לחץ הנציבות האירופית

לאחר שהנציבות האירופית חייבה את Meta לאפשר לבוטים חיצוניים לפעול בתוך WhatsApp, שב ChatGPT לאפליקציה עבור משתמשים אירופאיים. הגישה זמינה דרך איש הקשר המאומת 1-800-CHATGPT, כאשר המשתמשים יכולים לשוחח עם המודל ישירות מהצ'אט. המהלך הוא תוצאה ישירה של דין ה-DMA (Digital Markets Act) שנכנס לתוקף ומחייב את "שומרי הסף" הדיגיטליים לפתוח את הפלטפורמות שלהם.

## How To — Claude Code

### קריאות כלים במקביל (Parallel Tool Calls)

אחד הדברים החזקים ביותר ב-Claude Code הוא היכולת להפעיל כמה כלים בו-זמנית במקום לחכות שכל אחד יסתיים לפני שמפעילים את הבא. זה נקרא **Parallel Tool Calls**, וזה יכול לקצר משמעותית את זמן הביצוע של משימות מורכבות.

**למה זה חשוב?**
כאשר Claude פועל בסדרה (אחד אחרי השני), כל כלי מחכה לכלי הקודם. אם אתם צריכים לקרוא 5 קבצים שונים, תצטרכו לחכות 5 פעמים. עם קריאות מקביליות, כל 5 הקריאות יוצאות בו-זמנית ומגיעות בבת-אחת — וכך זמן הביצוע הכולל הוא בערך כמו זמן הקריאה של קובץ אחד בלבד.

**איך זה עובד בפועל?**
Claude מזהה באופן אוטומטי מתי פעולות הן *עצמאיות* זו מזו — כלומר, כשתוצאת הפעולה הראשונה לא נדרשת כדי להתחיל את השנייה. לדוגמה:
- קריאת מספר קבצים שאינם תלויים זה בזה
- חיפוש מקביל עם `Grep` ועם `Glob` בו-זמנית
- הרצת פקודות Bash שאינן משנות את אותה סביבה

**איך לגרום ל-Claude לנצל את זה?**
הנוסחה הפשוטה: פרטו את כל מה שאתם רוצים **בהוראה אחת**. במקום לכתוב "קרא את קובץ A, ואחר כך קרא את קובץ B", כתבו: "קרא את קבצי A, B ו-C ותסכם אותם". כאשר Claude רואה שהמשימות בלתי-תלויות, הוא יוציא אותן במקביל.

**ב-Workflows ו-Agents מתקדמים:**
בסקריפטי Workflow, ניתן להשתמש ב-`parallel()` ו-`pipeline()` כדי לתאם מאות סוכנים שעובדים בו-זמנית. `pipeline()` היא ברירת המחדל המומלצת — היא מריצה כל פריט בכל השלבים ברצף, בלי חסמים בין שלבים. `parallel()` מוסיפה חסם (barrier) שממתין לכל התוצאות לפני שממשיכים — שימושי רק כשצריך את כל התוצאות לפני שלב הבא.

**תוצאה:** מה שלוקח לפעמים דקות — כשכלים מחכים בתור — יכול להסתיים תוך שניות ספורות. הפחתת זמן ההמתנה היא אחד הדברים הראשונים שמרגישים כשמתחילים לעבוד עם Claude Code ביעילות.

## סקיל שכדאי להכיר

### /verify — אימות חזותי של פיצ'ר

הסקיל `/verify` נועד לפתור בעיה נפוצה: לא מספיק שהקוד עובר טסטים — צריך לראות שהפיצ'ר *עובד באמת* מבחינת המשתמש הסופי. `/verify` מפעיל את הפרויקט בפועל, מנווט בדפדפן אל הפיצ'ר המבוקש, ומוודא שהוא מתנהג כמצופה — גם על ה-happy path וגם על edge cases.

**מתי להשתמש בו?**
אחרי שסיימתם פיצ'ר חדש ורוצים לאמת שהכל נראה ועובד נכון לפני שפותחים PR. במיוחד שימושי לשינויים ב-UI — צבעים, מיקומים, אינטראקציות — שסוג הבדיקות הרגיל לא יכול לאמת.

**מה הסקיל עושה בפועל?**
Claude מפעיל את שרת הפיתוח, מחכה שהאפליקציה תהיה זמינה, מנווט אוטומטית לדף הרלוונטי, בודק שהפיצ'ר מתפקד, ומוסר דיווח מפורט על מה שראה — כולל צילומי מסך אם יש תמיכה בכך. מדובר ב"עיניים" של Claude על המוצר האמיתי, לא רק על הקוד.
