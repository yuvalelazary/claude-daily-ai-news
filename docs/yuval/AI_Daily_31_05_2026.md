## How To — Claude Code

### Agents — שימוש בסוכני משנה להגנה על ההקשר

אחת היכולות החזקות ביותר ב-Claude Code היא הפעלת **סוכני משנה (Agents)** — מופעים נפרדים של Claude שמבצעים משימות עצמאיות ומחזירים תוצאה לסוכן הראשי, מבלי לזהם את ה-context הקיים.

**הבעיה שסוכני משנה פותרים**

כשעובדים עם Claude Code על פרויקטים גדולים, חלון ההקשר (context window) מתמלא מהר — קריאת עשרות קבצים, הרצת פקודות, ניתוח לוגים. כשה-context מתמלא, Claude "שוכח" מה היה בתחילת השיחה. סוכן משנה מאפשר להעביר משימה כבדה לסביבה נפרדת, שמחזירה רק את התוצאה הסופית — בלי לעלות על חלון ההקשר של הסוכן הראשי.

**סוגי סוכנים מיוחדים**

Claude Code כולל כמה סוגי סוכנים ייעודיים עם כלים מותאמים:

- **Explore** — סוכן חיפוש מהיר ולא-כתיבה בקוד. אידיאלי לאיתור קבצים לפי שם, grep על סמלים, או "איפה מוגדר X?". קורא קטעים בלבד ולא קבצים שלמים, כך שמהיר מאוד.
- **Plan** — ארכיטקט תוכנה שמכין תוכנית מימוש. מחזיר רשימת צעדים, מזהה קבצים קריטיים ומנתח חלופות ארכיטקטוניות.
- **claude** — סוכן כללי לכל שאר המשימות עם גישה לכל הכלים.

**דוגמה מעשית**

נניח שאתה מבקש מ-Claude לסקור בעיות אבטחה ב-20 קבצים. במקום שהסוכן הראשי יקרא את כולם ויאבד הקשר — Claude יכול לשלוח סוכן Explore שיחפש את הקבצים הרלוונטיים, ולאחר מכן סוכן claude שיבצע את הסקירה. כל סוכן מחזיר רק דוח מסכם, ה-context הראשי נשמר נקי.

**מתי להשתמש בסוכן משנה?**

- כשמשימה עצמאית ומחייבת קריאה של הרבה קבצים
- כשרוצים "חוות דעת שנייה" ניטרלית ועצמאית על קוד
- כשמריצים מספר משימות במקביל — למשל בדיקות אבטחה ובדיקות ביצועים בו-זמנית
- כשרוצים להגן על ה-context הראשי מהצפה של תוצאות ביניים

מינוף נכון של סוכני משנה יכול להכפיל ואף לשלש את יעילות העבודה עם Claude Code — במיוחד בפרויקטים גדולים ומורכבים עם מאות קבצים.

## סקיל שכדאי להכיר

### /security-review

הסקיל `/security-review` מבצע ביקורת אבטחה מקיפה ואוטומטית על כל השינויים שבוצעו ב-branch הנוכחי. במקום לבדוק ידנית בעיות כמו SQL injection, XSS, חשיפת מפתחות API, הרשאות שגויות, או שימוש לא בטוח בקלט משתמשים — Claude Code סורק את כל ה-diff ומחפש פגיעויות ידועות.

**מתי להשתמש בו?**

לפני כל Pull Request שמכיל קוד שמטפל בנתוני משתמשים, מתקשר עם APIs חיצוניים, מנהל הרשאות, אימות, או כל קלט שמגיע ממשתמשים לא מאומתים. זו שכבת הגנה אחרונה לפני שהקוד מגיע לסביבת הייצור.

**מה הסקיל בודק?**

הסקיל מחפש בין היתר: פגיעויות OWASP Top 10, שימוש לא בטוח במשתני סביבה, חשיפת מידע רגיש בלוגים, בעיות בניהול sessions וטוקנים, חוסר validation על קלטים, ופרמטרים קריטיים שלא עוברים sanitization. התוצאה היא דוח ממצאים ברור עם סדרי עדיפויות ומה שיש לתקן.

**כיצד מפעילים:** פשוט הקלד `/security-review` בתוך session של Claude Code כשה-branch שלך כבר כולל שינויים.
