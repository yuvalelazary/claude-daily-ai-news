## How To — Claude Code

### Hooks — פקודות אוטומטיות לפני ואחרי כל כלי

Hooks הם אחד המנגנונים החזקים ביותר ב-Claude Code. הם מאפשרים לך להגדיר פקודות shell שירוצו אוטומטית לפני שכלוד משתמש בכלי כלשהו (PreToolUse) או אחרי שהוא סיים (PostToolUse). בעזרת Hooks תוכל לאכוף כללי עבודה, לנהל לוגים, להפעיל בדיקות אוטומטיות, ואפילו לעצור פעולות מסוכנות לפני שיתבצעו.

**סוגי Hooks הזמינים:**

- **PreToolUse** — רץ לפני שכלוד מפעיל כלי. אם ה-Hook מחזיר קוד יציאה שאינו אפס, הכלי לא יופעל כלל. שימושי מאוד לחסימת פעולות מסוכנות כמו מחיקת קבצים קריטיים.
- **PostToolUse** — רץ אחרי שהכלי הסתיים. שימושי לרישום לוגים, הפעלת בדיקות, או שמירת גיבויים אוטומטיים.

**איך מגדירים Hooks?**

מוסיפים את ההגדרה לקובץ `.claude/settings.json` בתיקיית הפרויקט (לכלל חברי הצוות) או ל-`~/.claude/settings.json` (אישי בלבד):

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [
          {
            "type": "command",
            "command": "npm run lint --silent"
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"[$(date)] bash: $CLAUDE_TOOL_INPUT\" >> ~/claude-audit.log"
          }
        ]
      }
    ]
  }
}
```

**דוגמאות לשימושים נפוצים:**
- הרצת linter אוטומטי אחרי כל עריכת קובץ
- שמירת snapshot לפני מחיקת קבצים
- שליחת התראה ל-Slack כאשר נעשים שינויים קריטיים
- בדיקת שהכלי `git push` לא מבוצע ישירות ל-`main`
- רישום ביקורת מלאה של כל הפקודות ש-Claude מריץ

Hooks הם הדרך האידיאלית לשלב את Claude Code בתוך תהליכי העבודה הקיימים שלך ולוודא שהוא עובד לפי כללי הצוות — אוטומטית, בכל פעם, ללא צורך להזכיר לו בכל שיחה מחדש.

## סקיל שכדאי להכיר

### /review

הסקיל `/review` מריץ סקירת קוד מלאה של כל השינויים בענף הנוכחי לפני פתיחת Pull Request. כלוד קורא את כל הקבצים שהשתנו, מנתח את הלוגיקה, מחפש באגים פוטנציאליים, בעיות ביצועים, ופגיעויות אבטחה — ומחזיר דוח מסודר עם ממצאים וסדרי עדיפויות.

**מתי להשתמש:**
- לפני כל `git push` לענף משותף
- לפני פתיחת PR לסקירה על ידי עמיתים
- כשאתה לא בטוח שהקוד מוכן לביקורת חיצונית

**אפשרויות שימושיות:**
- `/review` — מדווח על ממצאים בלבד
- `/review --fix` — מיישם תיקונים אוטומטית
- `/review --comment` — מפרסם הערות ישירות כ-inline comments על ה-PR ב-GitHub

`/review` חוסך זמן יקר בסקירות קוד ידניות, מאפשר לתפוס בעיות מוקדם לפני שהן מגיעות ל-reviewer אנושי, ומשפר את איכות הקוד שנכנס לענף הראשי. כלי הכרחי לכל מפתח שעובד עם Pull Requests באופן קבוע.
