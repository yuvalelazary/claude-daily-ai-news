## How To — Claude Code

### עבודה עם Sub-Agents (סוכנים משניים)

אחת היכולות החזקות ביותר של Claude Code היא האפשרות לשלוח תת-משימות ל-**Agent נפרד** — במקום לטפל בכל הלוגיקה בתוך הסשן הראשי. זה מה שמכונה "Sub-Agent" או "Agent משני", וזו שיטת עבודה שיכולה לשנות לגמרי את האופן שבו אתם משתמשים ב-Claude Code על פרויקטים מורכבים.

**למה זה חשוב?**

כשאתם עובדים על משימה גדולה — נניח, בדיקת כל קבצי הפרויקט לאיתור בעיות אבטחה, או ריצה על רשימה ארוכה של קבצים וביצוע שינויים — הקונטקסט (ה"זיכרון הפעיל") של המודל מתמלא מהר. כשהקונטקסט מלא, Claude עלול לאבד מידע שנאסף קודם, ולהתחיל לבצע טעויות.

**הפתרון: Sub-Agents**

במקום לבצע הכל בסשן אחד, Claude Code יכול להפעיל Agent חדש ומנותק שמקבל משימה ספציפית, מבצע אותה עם קונטקסט נקי משלו, ומחזיר את התוצאה לסשן הראשי. כך הסשן הראשי נשמר נקי ומפוקס, והאגנט המשני יכול להתמקד במשימה בלי להיות מוסח ממידע לא רלוונטי.

**איך זה עובד בפועל?**

תוכלו לבקש מ-Claude לשלוח משימה לאגנט נפרד בכמה דרכים:
- "שלח זאת לאגנט נפרד כדי להגן על הקונטקסט הראשי"
- "הפעל Sub-Agent שיבדוק את כל הקבצים ב-/src"
- שימוש ב-`subagent_type` שמאפשר לכוון לסוג אגנט מסוים (Explore, code-reviewer וכו')

**מתי כדאי להשתמש?**

- בדיקת קוד על פרסי מסמכים או קבצים גדולים
- ריצה על עשרות קבצים ומשימות חוזרות בצורה מקבילה
- חקירה פתוחה של קודבייס גדול בלי לזהם את הקונטקסט הראשי
- ביצוע מטלות שיכולות לרוץ במקביל (כמה אגנטים בו-זמנית)

**יתרון נוסף: מקביליות**

Claude Code יכול להפעיל מספר Sub-Agents **בו-זמנית**. כלומר, במקום לבדוק 10 קבצים ברצף (אחד אחרי השני), אפשר לשלוח 10 אגנטים שרצים במקביל ולסיים פי עשרה מהר יותר.

Sub-Agents הם הכלי הנכון כשהמשימה גדולה מדי לסשן אחד — השתמשו בהם לחיסכון בזמן ולשמירת איכות הפלט.

## סקיל שכדאי להכיר

### /review

הסקיל `/review` הוא אחד הכלים המועילים ביותר ב-Claude Code לפני פתיחת Pull Request. כשמפעילים אותו, Claude מבצע סקירת קוד מלאה על כל השינויים שנמצאים בברנץ' הנוכחי — בדיוק כמו שמבקשים מעמית צוות לעשות Review לפני Merge.

הסקיל בודק מספר ממדים: נכונות לוגית, בעיות פוטנציאליות, כפילויות קוד, קריאות, וגם מציין מקומות שבהם הקוד יכול להיות פשוט יותר. הוא לא מחליף בדיקות אוטומטיות כמו טסטים ו-Linting — אלא מוסיף שכבת הבנה אנושית-AI שמזהה בעיות שכלים אוטומטיים מפספסים.

**מתי להשתמש?** לפני כל PR חשוב, בשלב שבין "סיימתי לכתוב" ל"דוחף לברנץ'". זה הזמן הנכון לתפוס בעיות לפני שהן מגיעות לעיני הצוות. שימוש קבוע ב-`/review` מוביל לקוד נקי יותר, PR-ים קצרים יותר, ותהליך Review מהיר ואיכותי יותר.
