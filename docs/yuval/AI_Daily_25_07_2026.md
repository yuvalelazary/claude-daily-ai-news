## How To — Claude Code

### /compact — דחיסת הקשר כשהשיחה הופכת לגדולה מדי

כאשר אתה עובד עם Claude Code על פרויקטים גדולים, שיחות ארוכות, או משימות מורכבות, חלון ההקשר (context window) עשוי להתמלא. כשזה קורה, Claude עלול להתחיל "לשכוח" פרטים מוקדמים בשיחה, להאט, או אפילו להפסיק לתפקד כראוי. הפקודה `/compact` נועדה בדיוק לפתרון בעיה זו.

**איך זה עובד?**
כשאתה מקליד `/compact`, Claude Code מסכם את כל השיחה עד כה לתמצית מדויקת — שומר את המידע הרלוונטי (קבצים שנדונו, החלטות שהתקבלו, בעיות שנפתרו) ומשחרר את השטח שתפסו ההודעות המפורטות המקוריות. התוצאה היא שיחה קצרה בהרבה שמכילה את כל מה שצריך — בלי הסחות דעת.

**מתי כדאי להשתמש?**
- כשאתה רואה אזהרה שהקשר מתקרב למגבלה
- אחרי שסיימת שלב גדול (למשל, ריפאקטורינג שלם של קובץ) ורוצה להמשיך לשלב הבא בצורה נקייה
- כשאתה מרגיש שהתשובות של Claude פחות מדויקות — לעיתים זה סימן שיש יותר מדי רעש בהקשר
- לפני שמתחילים משימה חדשה שאינה קשורה לקודמת

**טיפ מקצועי:** ניתן להוסיף הוראה לפקודה — למשל `/compact דגש על הקבצים שנערכו` — ו-Claude ישמר את המידע הספציפי הזה בסיכום. ככה אתה שולט בדיוק במה שנשאר בזיכרון.

**מה ההבדל בין /compact ל-/clear?**
`/clear` מוחק את כל ההקשר לחלוטין ומתחיל מאפס. `/compact` לעומת זאת, מבצע "ריכוז חכם" — לא מאבד מידע חיוני, רק מדחס אותו. לכן, כמעט תמיד עדיף להשתמש ב-`/compact` כשמרגישים שהשיחה כבדה מדי, ולשמור את `/clear` למקרים שבהם רוצים להתחיל נושא חדש לגמרי.

השימוש הנכון ב-`/compact` יכול להאריך משמעותית את אורך הסשן הפרודוקטיבי שלך עם Claude Code ולחסוך זמן רב בעבודה על פרויקטים גדולים.

## סקיל שכדאי להכיר

### /security-review

הסקיל `/security-review` מבצע ביקורת אבטחה מקיפה על כל השינויים שנעשו בענף הנוכחי בהשוואה ל-main. במקום לסרוק קוד ידנית לבעיות אבטחה — דבר שלוקח שעות ודורש מומחיות — הסקיל הזה מפעיל סוכן מתמחה שבודק את הקוד שלך מזוויות מרובות: חדירות SQL injection, XSS, חשיפת מפתחות API, ניהול לא בטוח של הרשאות, ועוד.

מאחורי הקלעים, הסקיל מנחה את Claude לעבור על כל הדיף בין הענף שלך ל-main, לזהות דפוסים מסוכנים, ולהציג ממצאים עם הסברים ברורים לגבי הסיכון ואיך לתקן. הוא מיועד לשימוש לפני כל merge לסביבת ייצור — ויכול לחסוך אירוע אבטחה שלם. פשוט הקלד `/security-review` בכל שלב לפני פתיחת pull request.
