## How To — Claude Code

### Worktrees — עבודה על כמה ענפים בו-זמנית

כשאתם עובדים עם Git, לרוב אתם מחליפים ענפים דרך `git checkout` — מה שמחייב לנקות את סביבת העבודה, לשמור שינויים, ולחכות. **Worktrees** של Git פותרים בדיוק את הבעיה הזו: הם מאפשרים לכם לפתוח כמה ספריות עבודה נפרדות, כל אחת על ענף שונה — בו-זמנית, ללא החלפה.

כשעובדים עם Claude Code, Worktrees שימושיים במיוחד כשצריך לטפל בבאג דחוף בענף `main` בזמן שהמודל ממשיך לפתח פיצ'ר בענף אחר. במקום להפריע לעבודה, פותחים Worktree נפרד.

**איך עושים את זה:**

```bash
# יצירת worktree חדש לענף קיים
git worktree add ../my-project-fix fix-branch

# יצירת ענף חדש ישירות ב-worktree
git worktree add -b new-feature ../my-project-feature main

# הצגת כל ה-worktrees הפעילים
git worktree list

# הסרה לאחר שסיימתם
git worktree remove ../my-project-fix
```

**בתוך Claude Code**, כשמריצים סוכן במצב מבודד (isolation: worktree), המערכת יוצרת Worktree אוטומטית עבור אותו סוכן — כך שהוא עובד על עותק נפרד של הקוד ולא משבש שינויים אחרים. זה שימושי במיוחד כשמפעילים מספר סוכנים במקביל שכולם צריכים לשנות קבצים.

**יתרונות מרכזיים:**
- ניתן להריץ טסטים בענף אחד בזמן שמפתחים בענף אחר
- אין צורך ב-`git stash` כל פעם שרוצים להחליף הקשר
- כל Worktree שומר את ה-index וה-working tree שלו בנפרד
- אידיאלי לניהול PR hotfix בלי לעצור פיתוח ראשי

לשימוש ב-Claude Code: אפשר לבקש מ-Claude להפעיל סוכן עם `isolation: "worktree"` כדי להבטיח שעבודה מקבילית לא מתנגשת. המערכת מסדרת ומנקה את ה-Worktree אוטומטית בסיום המשימה אם לא נעשו שינויים.

## סקיל שכדאי להכיר

### /init

הפקודה `/init` היא אחת השימושיות ביותר כשמתחילים לעבוד עם Claude Code על פרויקט קיים. במקום להסביר ידנית לקלוד מה הפרויקט עושה, איך הוא בנוי, אילו כלים הוא משתמש וכיצד להריץ אותו — `/init` עושה את כל זה אוטומטית.

כשמריצים `/init`, Claude Code סורק את כל הקוד בפרויקט, מנתח את מבנה הקבצים, קורא קבצי הגדרה כמו `package.json`, `pyproject.toml`, `Makefile` ועוד — ואז מייצר קובץ `CLAUDE.md` מותאם אישית בשורש הפרויקט. קובץ זה מכיל תיאור של הפרויקט, הוראות בנייה והרצה, הגדרות חשובות, ואזהרות שרלוונטיות לעבודה עם הקוד.

**למה זה חשוב?** כי בכל פעם שפותחים שיחה חדשה עם Claude Code, המודל קורא את `CLAUDE.md` אוטומטית ומיד "יודע" מה הפרויקט. זה חוסך המון זמן בהסברים חוזרים, מונע טעויות הנובעות מחוסר הקשר, ומבטיח שכל שיחה מתחילה מנקודת ידע מוצקה.

`/init` שימושי גם לצוותים — כשמשתף אחד מהמפתחים פרויקט עם עמית חדש, ה-`CLAUDE.md` הופך לתיעוד חי ועדכני שמסייע לכולם.
