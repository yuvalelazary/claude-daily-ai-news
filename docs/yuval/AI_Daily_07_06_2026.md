## How To — Claude Code

### Worktrees — עבודה על מספר ענפים Git בו זמנית

Worktrees הוא אחד הכלים החזקים ביותר ש-Claude Code תומך בהם — ורוב המשתמשים כמעט ולא מכירים אותו. בדרך כלל, כשרוצים לעבוד על ענף Git חדש, צריך לעשות `checkout` — כלומר, להחליף את הקוד שמוצג בתיקייה הנוכחית. הבעיה: אם אתם באמצע תיקון באג חשוב ופתאום מגיעה משימה דחופה, אתם צריכים או לדחוף לקומיט שאינו מוכן, או לאחסן שינויים ב-stash ולקחת סיכון לאבד אותם.

**Worktrees פותר בדיוק את הבעיה הזו.** באמצעות הפקודה `git worktree add`, ניתן לפתוח ענף נוסף בתיקייה נפרדת על אותו ה-repository — בלי לגעת בתיקייה הראשית.

**דוגמה מעשית:**
```bash
# פתיחת worktree חדש לענף feature
git worktree add ../my-project-feature feature-branch

# עכשיו אפשר לעבוד בשתי תיקיות במקביל:
# ~/my-project      ← ענף main (עבודה ראשית)
# ~/my-project-feature ← ענף feature (ב-worktree)

# הסרת ה-worktree בסיום
git worktree remove ../my-project-feature
```

**שימוש מתקדם ב-Claude Code SDK:**
כשמשתמשים בפרמטר `isolation: "worktree"` בקריאה ל-Agent, Claude Code יוצר worktree זמני על ענף מבודד אוטומטית. הסוכן עובד שם ללא מגע בקוד הראשי, ובסיום — אם לא היו שינויים — ה-worktree מנוקה לחלוטין. אם היו שינויים, מוחזרים הנתיב והענף לשימוש ידני.

**יתרונות עיקריים:**
- ניתן להריץ בדיקות על ענף אחד בזמן שמפתחים על ענף אחר
- אין צורך ב-stash כשעוברים בין משימות
- Claude יכול להריץ סוכן מבודד בלי לגעת בעבודה הנוכחית
- מצוין לביצוע code review על ענף אחר בזמן שממשיכים לפתח
- אידיאלי לסביבות CI שמריצות כמה ענפים בו זמנית

בסביבת Claude Code על ה-Web, Worktrees משמשים את הסוכנים הפנימיים לבידוד עבודה — ממש כמו שצוות פיתוח עובד: כל מתכנת על תיקייה שלו, ללא הפרעות הדדיות.

## סקיל שכדאי להכיר

### /review — ביקורת קוד מלאה לפני פתיחת PR

הסקיל `/review` מריץ סקירת קוד מקיפה על כל השינויים בענף הנוכחי לפני שפותחים Pull Request. במקום לפתוח PR ולחכות שחבר צוות יגלה בעיות — Claude עצמו עושה את הביקורת מראש, ומאפשר לתקן לפני שהקוד נחשף.

**מה הסקיל בודק:**
- שגיאות לוגיות ובאגים אפשריים
- בעיות ביצועים ויעילות
- קריאות קוד ועקביות עם שאר הפרוייקט
- הזדמנויות לפשט ולשפר קוד

**איך להשתמש:**
פשוט הקלד `/review` ב-Claude Code כשאתה על ענף עם שינויים. ניתן לשלוט ברמת העומק: `--low` לסריקה מהירה, `--medium` לסריקה רגילה, `--high` לניתוח מעמיק. ניתן להוסיף `--comment` כדי לפרסם ממצאים כ-inline comments ישירות על ה-PR ב-GitHub, או `--fix` כדי ש-Claude יתקן אוטומטית את הבעיות שמצא. זה סקיל שחוסך זמן רב בתהליך ה-review ומעלה את איכות הקוד שנשלח לקוד-בייס.
