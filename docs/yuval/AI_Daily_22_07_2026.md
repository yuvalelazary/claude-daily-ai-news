## How To — Claude Code

### הפקודה /init — יצירה אוטומטית של CLAUDE.md מפרויקט קיים

כשמגיעים לפרויקט חדש, אחד האתגרים הראשונים הוא להסביר ל-Claude את מבנה הקוד, הכלים בשימוש, האדריכלות, ואיך להריץ את הפרויקט. בלעדי הקשר זה, Claude נאלץ לחקור כל פעם מחדש — וזה בזבוז זמן גם עבורך וגם עבור ה-context window.

הפקודה `/init` פותרת בדיוק את הבעיה הזו. כשמריצים אותה בתיקיית הפרויקט, Claude סורק את כל המבנה: קבצי ה-package.json, ה-Dockerfile, ה-Makefile, ה-README, ומבנה התיקיות — ובונה אוטומטית קובץ `CLAUDE.md` שמכיל:

- **סקירת הפרויקט** — מה הפרויקט עושה ולמה הוא קיים
- **פקודות שכדאי לדעת** — כיצד לבנות, להריץ, לבדוק ולפרוס
- **מבנה הקוד** — איפה נמצאים הרכיבים החשובים
- **קונבנציות** — סגנון קוד, naming conventions, ודפוסים חוזרים בפרויקט

הקובץ `CLAUDE.md` נטען אוטומטית בכל פעם שפותחים סשן חדש בתיקייה זו, ומספק ל-Claude הקשר קבוע ועקבי מבלי שתצטרך להסביר כלום. זה שינוי תהומי בפרודוקטיביות — ה-AI מיד "מבין" את הפרויקט ויכול לעזור ביעילות גבוהה יותר.

מומלץ להריץ `/init` בתחילת כל פרויקט חדש, ולאחר שינויי ארכיטקטורה גדולים. ניתן גם לערוך את הקובץ שנוצר ולהוסיף מידע ידני כמו החלטות אדריכליות, כוונים עסקיים, או אזורים רגישים שכדאי ש-Claude יימנע מלגעת בהם. השילוב של סריקה אוטומטית עם הוספות ידניות מניב את תוצאות הפרודוקטיביות הטובות ביותר.

## סקיל שכדאי להכיר

### /run

הסקיל `/run` מאפשר ל-Claude לא רק לכתוב קוד — אלא גם להפעיל את הפרויקט ולראות בפועל שהשינויים שביצע עובדים כמצופה. במקום להסתמך רק על בדיקות יחידה או בדיקות טיפוסים, `/run` מפעיל את האפליקציה ומתבונן בהתנהגות האמיתית שלה.

כשמבקשים מ-Claude לבצע שינוי ומריצים לאחר מכן `/run`, הוא מחפש את הדרך המתאימה להפעלת הפרויקט — שרת web, כלי CLI, ממשק TUI, אפליקציית Electron, או סקריפט רגיל — ומריץ אותו. לאחר ההפעלה הוא יכול לצלם מסך, לבחון את הלוגים ולוודא שאין שגיאות בזמן ריצה.

הסקיל מועיל במיוחד כשעובדים על שינויים ב-UI: Claude מריץ את האפליקציה בדפדפן, רואה את המסך, ומאשר שהשינוי נראה כפי שתוכנן. זה מונע את הסיטואציה שבה הקוד עובר בדיקות אבל נראה שבור בפועל.
