## How To — Claude Code

### CLAUDE.md — הקובץ שהופך את Claude לשותף אמיתי לפרויקט שלך

כשאתה פותח שיחה חדשה עם Claude Code, הוא מתחיל עם אפס ידע על הפרויקט שלך. כל פעם אתה צריך להסביר מחדש את הארכיטקטורה, קונבנציות הקוד, כלי הבדיקה, ועוד. **CLAUDE.md** פותר בדיוק את הבעיה הזו — זהו קובץ Markdown שיושב בשורש הפרויקט, ו-Claude Code קורא אותו אוטומטית בתחילת כל סשן.

**מה לכתוב ב-CLAUDE.md?**

כתוב את מה שהיית אומר לעמית חדש שמצטרף לפרויקט ביומו הראשון:
- מה הפרויקט עושה ולמה
- איך להריץ את הסביבה (`npm install && npm run dev`)
- פקודות בדיקה חשובות (`npm test`, `pytest`, `make build`)
- קונבנציות קוד (שם משתנים, גדלי פונקציות, רמות הפשטה)
- תיקיות מרכזיות ומה תפקידן
- אזהרות ומלכודות ידועות ("אל תשנה קובץ X ישירות, קרא תחילה Y")

**דוגמה בסיסית:**

```markdown
# MyProject

## Setup
npm install && npm run dev

## Testing
npm test           # unit tests
npm run e2e        # end-to-end

## Conventions
- Components in PascalCase
- Hooks prefixed with `use`
- No inline styles — use Tailwind only

## Key folders
- src/api/     → backend routes
- src/ui/      → React components
- src/lib/     → shared utilities
```

**כיצד ליצור CLAUDE.md בצורה מהירה?**

אתה יכול להשתמש בסקיל `/init` שמייצר את הקובץ אוטומטית על בסיס ניתוח של קוד הפרויקט הקיים. פשוט הקלד `/init` בתוך Claude Code, וה-AI יסרוק את הרפוזיטורי ויכין טיוטה מוכנה לעריכה.

**מה מרוויחים?**

Claude Code עם CLAUDE.md טוב הוא כמו מפתח בכיר שמכיר את הפרויקט לעומק — ניחושים פחותים, טעויות פחות, תוצרים רלוונטיים יותר כבר מהפרומפט הראשון. זה חוסך עשרות דקות של הסבר מחדש בכל שיחה.

## סקיל שכדאי להכיר

### /simplify

הסקיל `/simplify` הוא כלי לניקוי ושיפור קוד שהשתנה לאחרונה. לאחר שסיימת להוסיף פיצ'ר או לתקן באג, לעיתים הקוד עובד — אבל הוא מסובך, מכיל כפילויות, או ניתן לייעול. `/simplify` סורק את השינויים שעשית (ה-diff הנוכחי) ומחפש: הזדמנויות לשימוש חוזר בלוגיקה קיימת, קוד שניתן לקצר, מבנים מיותרים, וחישובים לא יעילים.

**מתי להשתמש?** לאחר סיום תיקון שגיאה או הוספת פיצ'ר, לפני פתיחת PR, וכשמרגישים שהקוד שכתבתם ארוך מדי.

**איך מפעילים?** פשוט הקלד `/simplify` בתוך Claude Code — הסקיל יבחן את הקוד שהשתנה ויציע ויישם שינויים. שים לב: `/simplify` מתמקד **אך ורק** באיכות ופישוט — הוא לא מחפש באגים לוגיים (לצורך זה השתמש ב-`/review` או `/security-review`).
